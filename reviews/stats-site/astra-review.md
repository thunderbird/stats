# GPT 6 Astra independent code and visual review

Reviewed 2026-10-13 against `STATS_SITE_REDESIGN_PLAN.md`. This review covers both code and rendered visuals. No implementation files were edited.

**Disposition:** address the four findings below before final handoff. The main visual direction is successful: the restrained blue/violet palette, typography, spacing, chart width, and light/dark surfaces form a coherent dashboard. All four supplied screenshots were actually opened and inspected (`light-desktop.png`, `dark-desktop.png`, `light-mobile.png`, `dark-mobile.png`). The default mobile view fits its viewport; the custom editor has the specific layout defect below.

1. **P1 — Gate the add-on source switch on equivalent measures, not merely available records.** `docs/media/js/dashboard.mjs:675` enables Glean whenever its add-on records are nonempty. `stats_pipeline/glean_sql.py:201` defines the top ten by weekly Glean client counts, while the legacy collector uses the ATN popularity ranking (also acknowledged by `GLEAN_DATA_NOTES.md`). These are different measures. Moreover, the frontend never displays `glean.addons.comparison`, so the new graph presents the same “Excluding top 10 add-ons” label without disclosing the changed ranking. A fixture containing one Glean add-on week immediately switched the default view to Glean and omitted its comparison caveat. The approved requirement explicitly retains the current source if equivalent measures cannot be supported. **Fix:** retain the legacy default until an explicit equivalence check succeeds, or compute the same ATN exclusion set in Glean. A separately labeled exploratory Glean view can be offered, but it must disclose its different population/ranking and must not silently replace the requested equivalent comparison.

2. **P2 — Missing Glean weeks are drawn as continuous observations.** `docs/media/js/dashboard.mjs:621` enumerates only existing metric records, and `basicSeries` at `docs/media/js/dashboard.mjs:394` maps only those dates. `dimensionCard` at `docs/media/js/dashboard.mjs:804` and add-ons at `docs/media/js/dashboard.mjs:683` do the same. The renderer correctly handles explicit nulls, but cannot break at dates never supplied. With observed fixture weeks 2026-09-20 and 2026-10-04 and no 2026-09-27 record, the actual SVG was a continuous `M60,110.333L1182,27` line. Failed, unobserved, and not-yet-backfilled weeks therefore look like uninterrupted data; leading/trailing gaps also disappear. **Fix:** build a complete weekly timeline from the applicable collection/coverage bounds, insert null values for missing records, and ensure label defaults do not convert a wholly absent record into zero. Verify both line and stacked percentage charts and CSV exports with a missing middle week.

3. **P2 — Detailed-version search cannot find versions outside the hard-coded top nine.** `docs/media/js/dashboard.mjs:261` always passes `maxSeries: 10`; `docs/media/js/explorer-model.mjs:216` folds the rest into Other versions; `docs/media/js/dashboard.mjs:319` searches only the resulting capped series. On the real six-month data, Detailed versions showed nine named versions plus Other versions, and searching `115.0` returned no items even though that version has observations on all 184 dates in the range (5,264 on 2026-04-10). The data table and CSV also contain only the aggregated Other bucket. “Show all series” only resets visibility and cannot recover those versions. **Fix:** retain the readable default cap, but provide a full searchable version selector/search promotion or an explicit show-all mode so users can select any recorded version and export it. Make the cap/Other meaning visible. Keep exact remainder accounting when adding a searched version.

4. **P2 — The mobile custom editor puts Include versions in the color column.** `docs/media/css/dashboard.css:1252` changes the grid to three columns with a narrow first column, but only the third and fourth labels receive explicit placement. The fifth label (Include versions, generated at `docs/media/js/dashboard.mjs:379`) auto-flows into column one. At a 375 px viewport its text input measures **35.59 px wide**, so even a single version cannot be read; the screenshot also shows its label wrapping to two tiny lines. **Fix:** explicitly place the version-selector label across columns 2 through the end, or use full-width stacked fields on mobile and put row actions on their own line. Inspect both themes with populated long include/exclude rules. Evidence: `build/review/astra-mobile-editor.png`.

**Additional nonblocking observations:**

- The approved “ESR version families” and “Individually selected versions” presets are absent from the preset menu (`docs/index.html:232`). Manual rules can express these, but the shipped presets do not yet match the agreed set. Likewise, the editor does not expose the model's `excludeChannels` field.

- The obsolete lower-population palette repeats colors among the many detailed/legacy series. This is mostly a readability issue once the cap is made user-controllable; use selection and interactive legends to keep comparisons legible rather than simultaneously displaying every series.
